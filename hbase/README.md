# HBase Model Metrics Storage

## Overview

Apache HBase was used to store the machine-learning performance metrics generated by the Spark MLlib application.

The HBase table created for this project was:

```text
wine_quality_metrics
```

The table uses a single column family:

```text
metrics
```

## Table Design

The table was created in the HBase shell using:

```text
create 'wine_quality_metrics', 'metrics'
```

The `metrics` column family stores the evaluation results produced by the Spark Linear Regression model.

The Spark application uses the following row key:

```text
linear_regression
```

Using the model name as the row key makes it possible to identify which machine-learning model produced the stored metrics.

## Empty Table Verification

Before the Spark application was executed, the table was scanned using:

```text
scan 'wine_quality_metrics'
```

The initial scan returned zero rows. This confirmed that the HBase table existed but did not contain model-performance metrics before Spark wrote its results.

## Metrics Written by Spark

After training and evaluating the model, Spark wrote the following values into the `metrics` column family:

- `metrics:rmse` - Root Mean Squared Error
- `metrics:mae` - Mean Absolute Error
- `metrics:r2` - R-squared
- `metrics:model` - Machine-learning model name
- `metrics:timestamp` - Time the metrics were written

Spark communicated with HBase through the HBase Thrift server using the Python HappyBase library.

## Populated Table Verification

After the Spark MLlib application completed, the HBase table was scanned again using:

```text
scan 'wine_quality_metrics'
```

The second scan showed the `linear_regression` row and the stored model-performance metrics.

This populated scan confirmed that the final portion of the pipeline operated successfully:

```text
Spark MLlib → HappyBase → HBase Thrift Server → HBase
```
